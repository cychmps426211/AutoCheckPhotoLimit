# 0009. 引入定時推播機制與零警報靜默節流策略

## 背景與問題
1. **主動巡檢需求**：
   現場維修師於週一至週五早晨 08:00 開始日常巡檢，若需手動開啟聊天室輸入指令查詢，容易遺漏缺紙警報；主動發送當日低存量機台清單可顯著提升維護效率。
2. **與 ADR-0002 衝突與額度限制**：
   [ADR-0002](0002-line-reply-token-only.md) 全面禁止 `push_message` 以追求絕對零成本。然而 Line 官方帳號免費方案每月提供 200 則免費 Push 額度。在僅有 2 位維修師的使用場景下，單次推播僅扣 2 則，整月（約 22 工作日）最多消耗 44 則，存在充分的安全邊界。

## 決策
1. **局部解除 ADR-0002 限制**：
   - 僅允許「定時推播」任務使用 Line Push/Multicast/Broadcast API。
   - 所有使用者主動觸發之對話與即時查詢，依然嚴格維持使用 `replyToken` 被動回覆，絕不消耗 Push 額度。
2. **零警報靜默節流（Zero-Report Suppression）**：
   - 定時執行預設查詢時，若所有機台剩餘張數皆大於門檻（存量充足、無異常機台需補充），系統**靜默不發送任何訊息**。
   - 僅在存在小於等於門檻（`<= 20` 張）之警報機台時才進行推播，將推播頻率壓縮至最低，杜絕訊息疲勞與額度浪費。
3. **外部排程與安全金鑰端點**：
   - 由外部定時排程服務（如 cron-job.org）於週一至週五 08:00 (UTC+8) 發送帶有密鑰之 POST（或相容外部排程之 GET）請求至 `/tasks/daily-push`。
   - 端點支援透過 HTTP Header (`X-Task-Token`) 或 URL 查詢參數 (`?token=`) 提供安全金鑰並實施時序安全比對驗證，若未配置或不符一律拒絕（HTTP 401），阻擋未授權存取與惡意刷額度。
4. **全自動重新登入保護**：
   - 定時任務直接調用內建 `SessionManager`，若後台會話過期，自動透過離線 OCR 辨識驗證碼並登入，不需人工介入。
5. **採用全體廣播（Broadcast API）發送**：
   - 鑑於目前官方帳號僅有 2 位現場維修師使用，推播採用 `MessagingApi.broadcast()` 發送，無須額外設定或維護維修師個人 Line User ID 或 Group ID。
   - 若未來好友人數顯著擴張，可再平滑切換為指定 User ID 之多播（Multicast）。

## 影響與後果
- 維修師於工作日早晨能精準且被動接收缺紙警報，無缺紙時不被打擾。
- 每月推播訊息量預估在 10 ~ 30 則之間，完全受控於 200 則免費配額內。
- 新增安全端點與定時推播邏輯，相關測試涵蓋率與 CI 流程同步落實。
