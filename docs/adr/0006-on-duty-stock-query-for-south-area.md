# 0006. 新增南區值班底片殘量查詢模式 (area=46, s=0)

## 背景與問題
1. **值班巡檢範圍擴展**：
   現場維修師平時僅負責自己名下機台（與特定協同機台），但輪值值班時，責任範圍擴展至整個區域（例如南區所有機台）。
2. **後台網址與全區查詢規範**：
   後台系統之全區查詢網址為 `https://dl02.seiwainc.com.tw/pc/Paper/PaperMachine.php?area=46&s=0`，其中 `area=46` 代表南區，`s=0` 代表全部狀態。
   在該模式下，查詢不限定單一維修師（`uno=0`），南區全體機台數達 130 餘台。
3. **Line 訊息限制與警報聚焦**：
   若無門檻直接回傳全區 130 餘台機台，不僅會超出 Line Messaging API 單則訊息 5000 字元的硬性限制導致發送失敗，現場值班同仁也無法快速鎖定缺紙急迫機台。
4. **跨維修師聯繫資訊缺乏**：
   值班人員跨區巡檢時，需要知悉特定缺紙機台平時由哪位維修師負責，以便於現場協調與進度回報。

## 決策
1. **設定抽離與動態覆寫**：
   - 於 `src/config.py` 配置 `DUTY_AREA_NO = 46` 與 `DUTY_AREA_NAME = "南區"`，支援環境變數自訂其他責任區域。
2. **爬蟲層支援全區查詢與責任維修師解析**：
   - `PaperCrawler` 支援全區查詢（`uno=0`），發送請求至後台 API 時帶入 `AreaNo=46, UserNo=0, Status=0`，Referer 精確匹配 `PaperMachine.php?area=46&s=0`。
   - 在 `MachineStock` 資料結構中擴充 `in_charge: str`，於資料解析時提取後台回傳之 `InCharge`（負責維修師姓名）。
   - 當 `uno=0` 時，若資料為空則不拋出 `TechnicianNotFoundError`，視為該區域機台皆充足（或無機台）。
   - 保留異常機台排除邏輯（過濾 `ABC158-ND 高雄職訓中心`）並套用緊急排序（剩餘張數由少至多）。
3. **值班專用自然語言指令**：
   - `CommandParser` 擴充正則匹配：
     - 預設值班指令：「值班」、「值班底片」、「值班底片殘量」、「值班檢查底片」、「檢查值班底片」。
     - 帶門檻值班指令：「值班 < 20」、「值班底片 < 30」、「值班 20張」等。
   - 解析產生 `action="duty_query"`，預設帶入 `threshold=20`。
4. **值班專屬訊息排版**：
   - `MessageBuilder.build_duty_stock_report` 標記 `【南區值班 機台底片存量警報】`。
   - 警報機台附加標示 `[負責維修師: {in_charge}]`，清晰呈現現場對應人員。
   - 更新教學說明訊息，提示值班查詢指令用法。

## 影響與後果
- 維修師值班時僅需輸入「值班」或「值班底片殘量」，即可立即取得南區所有剩餘張數 <= 20 張之機台，並清楚知悉每台機台負責人員。
- 預設門檻 20 張有效防止訊息過長被 Line 拒收，兼具靈活性（可隨時自訂「值班 < 50」擴大監控）。
- 異常機台 `ABC158-ND` 在值班模式中持續被自動過濾，防止誤導值班人員。
